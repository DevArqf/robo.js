# Robo CLI

The Robo.js CLI helps you manage your bot project like a boss. Here's a quick overview of the available commands and options.

```sh
Options:
  -V, --version         output the version number
  -h, --help            display help for command

Commands:
  dev [options]         Ready, set, code your bot to life! Starts development mode.
  start [options]       Starts your bot in production mode.

  build [options]       Builds your bot for production.
  build plugin          Optimizes your source files to be published as a plugin via npm.

  add [options]         Installs and registers a plugin.
  remove [options]      Uninstalls and unregisters a plugin.
  sync [options]        Syncs plugins with package.json.

  deploy [options]      Deploys your bot to RoboPlay!
  invite                Generates a link for servers to add your Robo.

  upgrade               Updates Robo.js and all installed plugins.
  help [command]        Display help for command
```

## Running

### dev

The primary way to run your Robo during development. It behaves similarly to `nodemon` or `ts-node-dev`, restarting your project when changes are detected. This command runs `build` behind the scenes, automatically updating bot commands.

```bash
robo dev [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-id, --instance-id` | Specify the instance ID to use |
| `-l, --log-level` | Specify the log level (debug, info, warn, error) |
| `-m, --mode` | Specify the mode(s) to run in (dev, beta, prod, etc.) |
| `-s, --silent` | Do not print anything |
| `-t, --tunnel` | Expose your local server to the internet via Cloudflare |
| `-v, --verbose` | Print more information for debugging |

### start

Used for running your Robo in production after running `build`. This is only necessary if you're self-hosting instead of using RoboPlay to host your Robo for free.

```bash
robo start [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-id, --instance-id` | Specify the instance ID to use |
| `-l, --log-level` | Specify the log level (debug, info, warn, error) |
| `-m, --mode` | Specify the mode(s) to run in (dev, beta, prod, etc.) |
| `-s, --silent` | Do not print anything |
| `-v, --verbose` | Print more information for debugging |

## Building

### build

Prepares your project for production by compiling your source files, generating a manifest file, and registering any command updates. You need to run this command before using `start`.

```bash
robo build [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-d, --dev` | Build for development |
| `-m, --mode` | Specify the mode(s) to run in (dev, beta, prod, etc.) |
| `-s, --silent` | Do not print anything |
| `-v, --verbose` | Print more information for debugging |
| `-w, --watch` | Watch for changes and rebuild (plugins only) |

### build plugin

Works similarly to `build`, but optimizes your source files to be published as a plugin via npm.

```bash
robo build plugin [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-s, --silent` | Do not print anything |
| `-v, --verbose` | Print more information for debugging |
| `-w, --watch` | Watch for changes and rebuild |

For more control over command registration, see the **[Command Registration Guide](/discord-bots/command-registration)**.

## Plugins

### add

Installs a plugin from npm and registers it with your Robo. You can also use this command to install plugins from a local directory!

```bash
robo add <package> [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-f, --force` | Forcefully install & register packages |
| `-ns, --no-seed` | Skip the seeding of files from the plugin |
| `-s, --silent` | Do not print anything |
| `-t, --trigger` | Setup hook trigger context (add or create) |
| `-v, --verbose` | Print more information for debugging |
| `-y, --yes` | Auto-accept seed files |

### remove

Uninstalls a plugin from your Robo and removes its config file.

```bash
robo remove <package> [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-s, --silent` | Do not print anything |
| `-v, --verbose` | Print more information for debugging |

### sync

Syncs the Robo with the latest plugins and configurations. Detects new plugins in `package.json` and registers them, or removes plugins that are no longer present.

```bash
robo sync [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-s, --silent` | Do not print anything |
| `-v, --verbose` | Print more information for debugging |

## Distributing

### deploy

Bundles your Robo's source files and hosts it on RoboPlay for free (currently invite-only).

```bash
robo deploy [options]
```

| Option | Description |
|--------|-------------|
| `-h, --help` | Shows the available command options |
| `-s, --silent` | Do not print anything |
| `-v, --verbose` | Print more information for debugging |

### invite

Generates an invite link to add your Robo onto Discord servers with permissions and all. For more information on adding your bot, refer to the **[Adding to Discord Servers](/discord-bots/invite)** docs.

```bash
robo invite
```

## Cloud Commands

Manage your RoboPlay deployments.

### cloud status

Check the status of your deployed Robo.

```bash
robo cloud status
```

### cloud start

Start your deployed Robo.

```bash
robo cloud start
```

### cloud stop

Stop your deployed Robo.

```bash
robo cloud stop
```

### cloud logs

View logs from your deployed Robo.

```bash
robo cloud logs
```

## Other Commands

### upgrade

Updates Robo.js and all installed plugins to their latest versions.

```bash
robo upgrade
```

### help

Displays help for this CLI or a specific command.

```bash
robo help [command]
```

### cli

Inspect and manage CLI commands.

```bash
robo cli --inspect
```

Shows all registered CLI commands including those from plugins and extensions.

## Troubleshooting

### Shutdown logs appearing after terminal prompt

When running `robo dev` through package managers like **pnpm** or **npx**, you may notice that shutdown logs appear after the terminal prompt returns when pressing `Ctrl+C`. This looks like:

```
^C
Shutting down...
user@host:~/project$
Mock server stopped   <-- appears after prompt
```

**This is a known issue with how pnpm and npx handle SIGINT signals.** These package managers don't properly wait for child processes to complete before returning control to the terminal.

#### Workarounds

1. **Run robo directly** (recommended):
   ```bash
   ./node_modules/.bin/robo dev
   ```

2. **Use npm instead of pnpm/npx**:
   npm handles child process signals more reliably in most cases.

This is purely a cosmetic issue - your Robo still shuts down correctly and all cleanup operations complete properly. The logs just appear slightly out of order in the terminal.
