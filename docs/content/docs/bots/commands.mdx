**Slash Commands** are one of the primary ways to use your **Discord Bot**. They allow users to interact with your bot by typing `/` followed by the command name, maybe some options, and hitting enter.

Building **Slash Commands** is streamlined with **Robo.js**, which also handles **[automatic registration](#command-registration)**.

## Creating Slash Commands

Create a file in your project's `src/commands` folder named after your **Slash Command**.

<Tabs groupId="examples-script" items={['Javascript', 'Typescript']} persist>
  <Tab value="Javascript">
    ```javascript title="src/commands/ping.js"
    export default (interaction) => {
      interaction.reply('Pong!')
    }
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript title="src/commands/ping.ts"
    import type { ChatInputCommandInteraction } from 'discord.js'
    import type { CommandResult } from 'robo.js'

    export default (interaction: ChatInputCommandInteraction): CommandResult => {
      interaction.reply('Pong!')
    }
    ```
  </Tab>
</Tabs>

That's it! Your `/ping` command is fully set up—give it a try!

<Callout type="info">
  Don't see your new command? Try restarting your **[Discord Client](https://support.discord.com/hc/en-us/articles/360035675191-Discord-Testing-Clients)** to refresh your cache.
</Callout>

Alternatively, you can also return your reply directly.

<Tabs groupId="examples-script" items={['Javascript', 'Typescript']} persist>
  <Tab value="Javascript">
    ```javascript title="src/commands/ping.js"
    export default async () => {
      return 'Pong!'
    }
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript title="src/commands/ping.ts"
    import type { CommandResult } from 'robo.js'

    export default async (): Promise<CommandResult> => {
      return 'Pong!'
    }
    ```
  </Tab>
</Tabs>

This kicks in **[Sage Mode](./sage.mdx)**—a hidden power that handles interactions and defers slow async functions!

## Subcommands and Subcommand Groups

Wanna go deeper? Make a folder inside `src/commands` with the parent command name and its own files.

<Tabs groupId="examples-script" items={['Javascript', 'Typescript']} persist>
  <Tab value="Javascript">
    ```javascript title="src/commands/channel/lock.js"
    export default async (interaction) => {
      const everyoneRole = interaction.guild.roles.everyone
      await interaction.channel.permissionOverwrites.edit(everyoneRole, {
        SendMessages: false,
        AddReactions: false
      })

      return 'This channel is now locked!'
    }
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript title="src/commands/channel/lock.ts"
    import type { ChatInputCommandInteraction } from 'discord.js'
    import type { CommandResult } from 'robo.js'

    export default async (interaction: ChatInputCommandInteraction): Promise<CommandResult> => {
      const everyoneRole = interaction.guild.roles.everyone
      await interaction.channel.permissionOverwrites.edit(everyoneRole, {
        SendMessages: false,
        AddReactions: false
      })

      return 'This channel is now locked!'
    }
    ```
  </Tab>
</Tabs>

We can go even deeper with **Subcommand Groups**. Just add another folder inside the parent command folder.

## Customizing Commands

Give your commands some context with descriptions. You can do this by exporting a `config{:ts}` object from your command file.

```javascript
import { createCommandConfig } from 'robo.js'

export const config = createCommandConfig({
  description: 'Responds with Pong!'
})
```

For TypeScript users, you can add typings for both the `config{:ts}` object and the command result.

```typescript title="commands/ping.ts"
import { createCommandConfig } from 'robo.js'
import type { CommandResult } from 'robo.js'

export const config = createCommandConfig({
  description: 'Responds with Pong!'
})

export default (): CommandResult => {
  return 'Pong!'
}
```

The `config{:ts}` object also lets you customize stuff like locale translations, Sage options, and command timeouts. To understand more about the available duration options, check out the [configuration section](../framework/core/config.mdx).

## Command Options

Robo.js allows you to further customize your commands with options. You can define these options in your `config{:ts}` object and then access their values in your command function.

<Tabs groupId="examples-script" items={['Javascript', 'Typescript']} persist>
  <Tab value="Javascript">
    ```javascript title="commands/ping.js" showLineNumbers {5-11}
    import { createCommandConfig } from 'robo.js'

    export const config = createCommandConfig({
      description: 'Responds with Pong!',
      // [!code highlight:7]
      options: [
        {
          name: 'loud',
          description: 'Respond loudly?',
          type: 'boolean'
        }
      ]
    })

    export default (interaction) => {
      const loud = interaction.options.get('loud')?.value as boolean
      return loud ? 'PONG!!!' : 'Pong!'
    }
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript title="commands/ping.ts"
    import { createCommandConfig } from 'robo.js'
    import type { CommandResult } from 'robo.js'
    import type { CommandInteraction } from 'discord.js'

    export const config = createCommandConfig({
      description: 'Responds with Pong!',
      // [!code highlight:7]
      options: [
        {
          name: 'loud',
          description: 'Respond loudly?',
          type: 'boolean'
        }
      ]
    } as const)

    export default (interaction: CommandInteraction): CommandResult => {
      const loud = interaction.options.get('loud')?.value as boolean
      return loud ? 'PONG!!!' : 'Pong!'
    }
    ```
  </Tab>
</Tabs>

You can also use a second parameter next to the interaction object to access the options directly. These are automatically parsed and passed to your command function, with full type support too!

<Tabs groupId="examples-script" items={['Javascript', 'Typescript']} persist>
  <Tab value="Javascript">
    ```javascript
    import { createCommandConfig } from 'robo.js'

    export const config = createCommandConfig({
      description: 'Responds with Pong!',
      options: [
        {
          name: 'loud',
          description: 'Respond loudly?',
          type: 'boolean'
        }
      ]
    })

    export default (interaction) => { // [!code --]
    export default (interaction, options) => { // [!code ++]
      return options.loud ? 'PONG!!!' : 'Pong!'
    }
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript
    import { createCommandConfig } from 'robo.js'
    import type { CommandOptions, CommandResult } from 'robo.js'
    import type { CommandInteraction } from 'discord.js'

    export const config = createCommandConfig({
      description: 'Responds with Pong!',
      options: [
        {
          name: 'loud',
          description: 'Respond loudly?',
          type: 'boolean'
        }
      ]
    } as const)

    export default (interaction: CommandInteraction): CommandResult => { // [!code --]
    export default (interaction: CommandInteraction, options: CommandOptions<typeof config>): CommandResult => { // [!code ++] 
      return options.loud ? 'PONG!!!' : 'Pong!'
    }
    ```

    <Callout type="info">
      `createCommandConfig{:ts}` and `as const{:ts}` are important for TypeScript! `createCommandConfig{:ts}` creates a command configuration object with the correct type, which tells your editor which options are available for your command for better autocompletion and type checking.
    </Callout>
  </Tab>
</Tabs>

Want to explore more options? Check the [configuration section](../framework/core/config.mdx).

### Choices

You can have predefined choices for your options. Just add a `choices{:ts}` array to your option object.

<Tabs groupId="examples-script" items={['Javascript', 'Typescript']}>
  <Tab value="Javascript">
    ```javascript
    import { createCommandConfig } from 'robo.js'

    export const config = createCommandConfig({
      description: 'Chooses a color',
      options: [
        {
          name: 'color',
          description: 'Your favorite color',
          type: 'string',
          choices: [
            { name: 'Red', value: 'red' },
            { name: 'Green', value: 'green' },
            { name: 'Blue', value: 'blue' }
          ]
        }
      ]
    })
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript
    import { createCommandConfig } from 'robo.js'

    export const config = createCommandConfig({
      description: 'Chooses a color',
      options: [
        {
          name: 'color',
          description: 'Your favorite color',
          type: 'string',
          choices: [
            { name: 'Red', value: 'red' },
            { name: 'Green', value: 'green' },
            { name: 'Blue', value: 'blue' }
          ]
        }
      ]
    } as const)
    ```
  </Tab>
</Tabs>

Make sure each choice has a `name{:ts}` and `value{:ts}`. The `name{:ts}` is what the user sees, while the `value{:ts}` is what your command receives.

To dynamically generate choices instead of hardcoding them in advance, see **[Autocomplete](#autocomplete)**.

### Direct Messages

Control whether your command is accessible in direct messages with `contexts`.

```javascript
export const config = {
  // ... other config
  contexts: ['Guild', 'BotDM']
}
```

Adding `'BotDM'{:ts}` alongside `'Guild'{:ts}` allows the command to be used in direct messages. Remove `'Guild'{:ts}` if you want to restrict the command to direct messages only.

You can customize defaults in your **[Robo Config](../framework/core/config.mdx#defaults)**.

### Default Member Permissions

Use `defaultMemberPermissions{:ts}` to define server-based permissions for your command. This field accepts `PermissionFlagsBits{:ts}` from Discord.js, allowing you to specify which roles or permissions are needed to access the command in a server context.

```javascript
import { PermissionFlagsBits } from 'discord.js'

export const config = {
  // ... other config
  defaultMemberPermissions: PermissionFlagsBits.KickMembers // Only users who can kick members can use this command
}
```

<Callout type="warn">
  Remember, server admins can adjust these default permissions for their own servers. Also, due to a Discord quirk, default permissions might not apply as expected to subcommands.
</Callout>

{/* For a more comprehensive overview of command permissions in Discord, check out our [Permissions Guide](/docs/advanced/permissions). */}

### User Installs

By default, commands are only available in guilds where your bot is installed. You can change this behavior with `integrationTypes{:ts}`.

```javascript
export const config = {
  // ... other config
  integrationTypes: ['GuildInstall', 'UserInstall']
}
```

This allows your **Slash Commands** to be used in any server, even if your bot isn't installed there. Remove `'GuildInstall'{:ts}` if you want to allow commands only for users that have installed your bot.

You can customize defaults in your **[Robo Config](../framework/core/config.mdx#defaults)**.

<Callout type="info">
  Make sure you **[update your install settings](https://discord.com/developers/docs/tutorials/developing-a-user-installable-app#configuring-default-install-settings)** in the **[Discord Developer Portal](https://discord.com/developers/applications)** to allow user installs.
</Callout>

## Autocomplete

Autocomplete can take your commands to the next level by providing suggestions as users type. You can implement autocomplete by exporting an `autocomplete{:ts}` function in your command file.

<Tabs persist id="examples-script" items={['Javascript', 'Typescript']}>
  <Tab value="Javascript">
    ```javascript title="commands/choosa-a-color.js" showLineNumbers {21-25}
    import { createCommandConfig } from 'robo.js'

    export const config = createCommandConfig({
      description: 'Chooses a color',
      options: [
        {
          name: 'color',
          description: 'Your favorite color',
          type: 'string',
          autocomplete: true
        }
      ]
    })

    const colors = ['red', 'green', 'blue', 'yellow', 'black', 'white', 'pink', 'purple', 'brown']

    export default (interaction) => {
      return `You chose ${interaction.options.get('color')?.value}`
    }

    // [!code highlight:5]
    export const autocomplete = (interaction) => {
      const colorQuery = interaction.options.get('color')?.value
      const filtered = colors.filter((color) => color.startsWith(colorQuery))
      return filtered.map((colors) => ({ name: colors, value: colors }))
    }
    ```
  </Tab>
  <Tab value="Typescript">
    ```typescript title="commands/choosa-a-color.ts"
    import { createCommandConfig } from 'robo.js'
    import type { CommandResult } from 'robo.js'
    import type { CommandInteraction, AutocompleteInteraction } from 'discord.js'

    export const config = createCommandConfig({
      description: 'Chooses a color',
      options: [
        {
          name: 'color',
          description: 'Your favorite color',
          type: 'string',
          autocomplete: true
        }
      ]
    })

    const colors = ['red', 'green', 'blue', 'yellow', 'black', 'white', 'pink', 'purple', 'brown']

    export default (interaction: CommandInteraction): CommandResult => {
      return `You chose ${interaction.options.get('color')?.value}`
    }

    // [!code highlight:5]
    export const autocomplete = (interaction: AutocompleteInteraction) => {
      const colorQuery = interaction.options.get('color')?.value as string
      const filtered = colors.filter((color) => color.startsWith(colorQuery))
      return filtered.map((colors) => ({ name: colors, value: colors }))
    }
    ```
  </Tab>
</Tabs>

In this example, the `autocomplete{:ts}` function returns an array of colors that start with the user's input, providing a dynamic and responsive user experience.

Note: the type of the Interaction is: `AutocompleteInteraction{:ts}`

## Command Registration

The cherry on top? You don't need to manually register your commands. Robo.js handles it for you when you run `robo dev{:bash}` or `robo build{:bash}`, automatically! However, if things go sideways for some reason, you can use the `--force{:bash}` flag to force registration.

```package-install
npx robo build --force
```
This will also clean up any commands that are no longer in your `commands` directory. Pretty neat, right?
